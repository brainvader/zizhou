## Test as a Context（TaaC）— Zizou の開発哲学

### コンセプト

**Test as a Context (TaaC)** は Zizou の中核的な開発哲学である。

> テストファイルを書くことが、そのままコンテキスト定義になる。
> コンテキストを定義することが、テストを書くことと等価である。

これは **Context First = Test First Development** を意味する。

### 従来の TDD との違い

|                        | TDD                    | TaaC（Zizou）                          |
| ---------------------- | ---------------------- | -------------------------------------- |
| テストの目的           | 実装の正しさを証明する | コンテキスト（作業スコープ）を定義する |
| テストを書くタイミング | 実装前                 | 開発開始前（スコープ定義として）       |
| テストの副産物         | リグレッション防止     | LLM に渡すファイル群の自動特定         |
| コンテキストの定義     | 手動・暗黙的           | テストファイルから自動導出             |

### TaaC の開発フロー

```
1. テストファイルを書く
   → describe 名 = 作業コンテキスト名
   → import 群  = 作業スコープ（関与ファイル群）
   → it         = シナリオステップ

2. FileTree でテストファイルを選択
   → SourceGraph に関与ファイル群が自動表示される
   → describe 名が Subflow ラベルになる

3. そのスコープで LLM に修正を依頼する
   → LLM に渡すファイルが自動的に最小化される
   → トークン消費を削減しつつ文脈が明確になる

4. テストを実行して確認（CTX-23）
   → 実行結果を右ペインに表示
   → 失敗ログをコピーして LLM にペースト
```

### SourceGraph 上の表示ルール（TaaC）

```
選択対象: テストファイル（*.test.ts / *.spec.ts）のみ
表示内容: 選択テストファイルの import 先ノード群（depth=1）
          + そのテストファイルが属する test_suite の node_ids
除外:     node_modules 配下
初期状態: 空（テストファイルが選択されるまで何も表示しない）
キャッシュ: 最後に選択したテストファイルの状態を維持
```

### テストファイルが存在しない = コンテキストが未定義

TaaC において、テストファイルのないソースファイルはグラフに表示されない。
これは設計上の圧力として機能する：

> 「テストを書かないとスコープが定義できない」
> → テストファイルの存在がコンテキスト定義の前提条件になる

### コンテキストの粒度

```ts
// 1ファイル1コンテキストを推奨
// ファイル名がコンテキスト名の代わりになる

// fix-filetree-bug.test.ts
describe('Fix FileTree bug', () => {      // ← コンテキスト名
    // import 群がスコープを定義する
    it('ファイルをクリックすると選択される', () => { ... })
    it('選択状態が FileTree に反映される', () => { ... })
})
```
